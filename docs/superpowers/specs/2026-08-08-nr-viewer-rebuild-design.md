# NR Viewer 全課重建設計

## 背景

目標課程位於 `\\jieyu_nas\web\files\2015\08\20150804 NR 神放複習`，共 11 講，viewer 使用共用模板。現況主要問題如下：

- 章節摘要過長，且大量重複同步逐字稿，未形成可快速複習的整理稿。
- 章節標題常由高頻詞或口語殘句組成，無法指出單一診斷主題或判讀任務。
- 僅第一講有 72 張 frames，其餘 10 講沒有縮圖，視覺索引不完整。
- 講者原始內容與後續神經放射學補充未清楚分離，來源界線不足。

版面與使用體驗以 `\\jieyu_nas\web\courses\AILearn\` 為優良參考，但不直接複製其內容或建立另一套 viewer。

## 目標

本次採方案 2：改善正式 canonical `skills/lecture-to-notes/` 生成器，再以同一套流程重建整門 NR 課程。完成後應達成：

1. 11 講使用一致、可重複執行的生成與稽核流程。
2. 每章有聚焦標題、詳細整理稿、固定四項核心重點、清楚分離的編輯補充與可用縮圖。
3. JSON 成為單一內容來源，viewer、PBF、`.v4.md`、課程首頁與稽核報告皆可由流程重建。
4. 保留播放器、章節導覽、搜尋、深連結、同步逐字稿與跳播等既有核心能力。
5. 以備份、暫存驗證及原子替換保護 NAS 上的正式產物，單講失敗不得破壞其他講或原檔。

## 非目標

- 不更改既有章節的起訖時間或重新切分章節。
- 不建立 NR 專用生成器、第二套 viewer 或長期分岔模板。
- 不進行一次性的 NAS hotfix 來繞過 canonical skill 改善。
- 不把外部知識、一般醫學補充或編輯判斷偽裝成講者原話。
- 不臆造病例病史、影像徵象、診斷結果或其他原始資料未提供的病例細節。
- 不提交 NAS 產物、病患資料、敏感資料或其他與本設計無關的檔案。

## 設計原則

### 單一內容來源

每講的正式 JSON 是章節內容與媒體索引的單一來源。viewer、PBF、`.v4.md`、課程首頁索引及稽核報告均屬衍生檔，必須能由來源 JSON 與原始媒體重新產生，不得在衍生檔中維護只有該處存在的章節內容。

原始逐字稿仍由 SRT 提供，不將完整逐字稿複製進章節 JSON。viewer 依章節時間範圍讀取或連結相應逐字稿。

### 來源分離

講者內容與編輯補充必須保持可辨識的來源界線：

- `summary_zh` 與 `takeaways_zh` 以講者內容為主，可依神經放射學知識重新組織，使論述完整且適合複習。
- 一般背景知識、現代分類、額外鑑別診斷或教學提醒若不是講者明確陳述，必須放入 `editorial_notes_zh`。
- 編輯補充不得改寫成講者語氣，也不得用來填補無法由原始資料確認的病例細節。

### 可重建與可稽核

所有處理階段須保留明確輸入、輸出與驗證結果。失敗時應能指出是哪一講、哪一章、哪一項門檻未通過，並能只重跑失敗單位，而非依賴人工修改正式 viewer。

## 整體架構

```text
MP4 / SRT / existing JSON / frames / OCR / editorial references
                              |
                              v
                         extract
                              |
                              v
                          curate
                              |
                              v
                          rewrite
                              |
                              v
                       render + audit
                              |
                              v
JSON / viewer / PBF / .v4.md / course index / audit report
```

### 輸入

- MP4：播放、時間定位與影格擷取來源。
- SRT：原始逐字稿與章節內容依據。
- 現有 JSON：保留既有章節起訖時間、可沿用的標題與內容線索。
- frames：既有影格資產；第一講的 72 張 frames 應納入候選池。
- OCR：輔助辨識投影片文字、圖像主題與影格相關性。
- 神經放射學編輯補充：用於明確標示的 `editorial_notes_zh`，不得污染講者內容欄位。

### 處理階段

1. **extract**：配對每講 MP4、SRT、既有 JSON 與可用 frames，抽取章節逐字稿、候選影格及 OCR。
2. **curate**：依既有章節時間範圍選擇內容證據與每章最多 4 張代表影格，排除重複、模糊、無關或資訊量低的畫面。
3. **rewrite**：產生聚焦標題、詳細整理稿、四項核心重點與獨立編輯補充；不得變更章節時間。
4. **render**：由 JSON 生成 viewer、PBF、`.v4.md` 與必要索引資料。
5. **audit**：檢查內容、媒體、跨衍生檔一致性及互動功能，輸出逐講與全課稽核結果。

## 資料模型

每個章節至少包含以下欄位；既有時間欄位名稱可沿用，但語意與值不得因本次重建而改變。

```json
{
  "title": "Glioblastoma 的影像判讀與鑑別",
  "summary_zh": "約 250–600 字的繁體中文詳細整理稿。",
  "takeaways_zh": [
    "核心重點一",
    "核心重點二",
    "核心重點三",
    "核心重點四"
  ],
  "editorial_notes_zh": [
    "明確標示為編輯補充的一般神經放射學資訊。"
  ],
  "frames": [
    {
      "time": 123.45,
      "ocr": "辨識出的投影片文字",
      "path": "frames/lecture-01/chapter-03-01.jpg"
    }
  ]
}
```

### 欄位規則

#### `title`

- 描述單一診斷主題、解剖區域、影像徵象或判讀任務。
- 應讓讀者不開啟逐字稿也能理解本章重點。
- 不得使用高頻詞堆疊、無主詞口語殘句、純病例編號、空字串或模板式標題。

#### `summary_zh`

- 約 250–600 個中文字，原則上分成 1–2 段。
- 應是結構化的詳細整理稿，而非逐字稿截取、逐句改寫或重複字幕。
- 可重組講者論述順序以提升教學清晰度，但不得改變講者可確認的結論。
- 病例特定細節只能來自 MP4、SRT、既有 JSON、影格或可核對的 OCR。

#### `takeaways_zh`

- 必須正好 4 項，不得多於或少於 4 項。
- 每項應是可獨立閱讀的實質重點，避免同義重複與空泛提醒。
- 優先涵蓋關鍵影像表現、鑑別方向、判讀陷阱或臨床決策意義。

#### `editorial_notes_zh`

- 與講者內容分離，viewer 中以獨立「編輯補充」區塊呈現。
- 沒有必要補充時可為空陣列，但不得放置提示文字或 placeholder。
- 外部補充必須是一般性、可查證的神經放射學知識；不得補造本課病例資訊。

#### `frames`

- 每章最多 4 張，目標為 4 張代表影格；若可靠候選不足，可保留 1–3 張並在稽核報告說明。
- 全章 0 張視為失敗，不得以空白圖、重複圖或 placeholder 通過。
- 每張包含合法影片時間、OCR 文字與可解析的相對路徑。
- 影格時間必須落在該章起訖範圍內；如因關鍵畫面位於邊界需容許誤差，誤差值應由生成器統一設定並由稽核明確記錄。
- 路徑必須相對於 viewer 可解析的課程根目錄，不得寫入本機絕對路徑或 NAS 帳號資訊。

### 語言與術語

- 介面與內容使用繁體中文台灣用語，不得出現簡體中文。
- 醫學術語優先採常見英文加繁體中文說明，例如「diffusion restriction（擴散受限）」。
- 專有名詞的英文大小寫與縮寫應在同一講及全課保持一致。
- `.v4.md` 必須與 JSON 的標題、整理稿、核心重點及編輯補充同步更新。

## Viewer 設計

### 保留功能

重建不得移除或弱化以下功能：

- MP4 播放器。
- 章節導覽與目前章節狀態。
- 全文搜尋。
- 可分享的章節深連結。
- 與播放時間同步的逐字稿。
- 由章節、搜尋結果或逐字稿跳播至對應時間。

### 章節內容區

每章依序呈現：

1. 聚焦式章節標題。
2. 1–2 段詳細整理稿。
3. 固定 4 項核心重點。
4. 代表影格區。
5. 獨立「編輯補充」框；無補充時不顯示空框。
6. 可展開的逐字稿、OCR 與其他候選影格。

### 影格呈現

- 每章主要區最多顯示 4 張等尺寸縮圖，實際存在的 1–4 張均須完整顯示，不可裁掉影像中的重要內容。
- 以 4 張為重建目標；不足 4 張時版面仍須穩定，不顯示空白格或假圖。
- 縮圖可開啟較大檢視，並能跳至對應影片時間。
- 額外候選影格可放在展開區，但不得取代主要代表影格的品質要求。
- 桌面與窄螢幕均須保持可讀，縮圖與文字不得水平溢位或互相遮蓋。

### 搜尋與深連結

搜尋至少涵蓋章節標題、`summary_zh`、`takeaways_zh`、`editorial_notes_zh` 及逐字稿。搜尋結果應標示來源類型並可跳至章節或時間點。既有章節深連結在重建後仍應指向相同章節時間範圍；若識別字生成方式需要調整，必須提供穩定映射，避免既有連結無聲失效。

## 重建流程

### 1. Preflight

正式處理前逐項檢查：

- NAS 根目錄可讀且目標輸出位置可寫。
- 11 講的 MP4、SRT、既有 JSON 及講次識別可正確配對。
- 第一講既有 frames 可讀；其餘講次具備從 MP4 擷取影格的條件。
- OCR、影格擷取、JSON 驗證、viewer/PBF/Markdown 產生與瀏覽器測試依賴均可用。
- 暫存與備份空間足夠。
- canonical `skills/lecture-to-notes/` 與同步腳本狀態一致，沒有未處理 drift。

Preflight 未通過時不得寫入正式產物，報告須列出缺少的檔案、配對衝突或依賴錯誤。

### 2. 改善 canonical 生成器

所有通用能力應實作於 `skills/lecture-to-notes/`，包括資料模型、內容規則、影格策展、render 及 audit。不得新增 NR 專用長期分岔。修改 canonical skill 後必須執行：

```bash
python sync_skills.py
python sync_skills.py --check
```

`--check` 必須成功，確保各代理使用的衍生 copy 與 canonical 版本一致。

### 3. 單講試跑與抽樣

先以 fixture 驗證完整管線，再選 Brain tumor、Vascular、Spine 三講作代表性抽樣。三講涵蓋不同內容結構與影像型態，用於確認標題、重寫品質、影格選擇、OCR、viewer 互動與衍生檔一致性。

抽樣未通過時不得直接進入全課正式替換；應修正 canonical 流程後重新產生抽樣講次。

### 4. 全課重建

- 逐講執行 extract、curate、rewrite、render 與 audit。
- 每講以獨立暫存目錄產生完整產物，避免半成品進入正式路徑。
- 長流程須持續輸出 cp950 相容的進度訊息，包括目前講次、階段、章節數、已完成比例與失敗摘要；不得靜默長跑。
- 單講失敗時記錄錯誤、保留原正式檔並繼續處理其他講次。
- 全部 11 講完成後執行跨講一致性與全課稽核。

### 5. 正式切換

每講的暫存產物須先通過內容、結構、路徑與功能驗證，才可原子替換正式檔。課程首頁只能在 11 講全部重建且全課稽核通過後更新，避免首頁指向新舊混合或缺漏的課程狀態。

## 安全寫入與備份

正式寫入前，為下列既有產物建立帶日期與時間的備份：

- 原始或現行 JSON。
- viewer HTML 與相關靜態資產。
- PBF。
- `.v4.md`。
- 課程首頁。
- 既有稽核報告。

寫入規則如下：

1. 備份與新產物不得覆蓋彼此，命名須能追溯來源講次與建立時間。
2. 所有新產物先寫入同一檔案系統中的暫存路徑，以便使用原子 rename/replace。
3. 暫存檔通過 schema、內容、路徑、章節一致性及必要功能檢查後，才替換正式檔。
4. 替換任何一項失敗時，該講視為失敗；保留原正式檔，並清楚記錄是否需要由備份回復。
5. 單講失敗不得阻止其他講次產生與稽核，但不得更新全課首頁。
6. 備份、暫存與稽核過程不得將敏感資料複製到 Git 工作區。

## 錯誤處理

錯誤至少分為以下類型，報告須包含講次、章節、階段、原始錯誤與處置結果：

- **輸入錯誤**：MP4/SRT/JSON 缺漏、重複配對、時間範圍非法。
- **內容錯誤**：標題失焦、摘要不符長度、核心重點不是 4 項、簡體中文、placeholder 或來源混淆。
- **影格錯誤**：無候選影格、擷取失敗、時間越界、路徑不存在、OCR 失敗或 0 張主要影格。
- **渲染錯誤**：JSON、viewer、PBF、`.v4.md` 章節數或標題不一致。
- **功能錯誤**：影片、縮圖、搜尋、深連結、跳播或逐字稿同步不可用。
- **寫入錯誤**：備份失敗、權限不足、磁碟空間不足、暫存驗證失敗或原子替換失敗。

可降級但不可隱藏的情況，例如單張 OCR 無法辨識，應保留影格並將 OCR 設為空字串或明確的無辨識結果，再由稽核判斷是否仍具視覺價值。會造成資料不完整、來源混淆或正式檔風險的錯誤不得降級通過。

## 品質門檻

### 章節內容

每章必須同時滿足：

- 標題聚焦於單一診斷主題、影像徵象或判讀任務。
- `summary_zh` 約 250–600 個中文字，為 1–2 段詳細整理稿，且不是逐字稿重複。
- `takeaways_zh` 正好 4 項，內容具體且彼此不重複。
- 講者內容與 `editorial_notes_zh` 清楚分離。
- 不含簡體中文、模板提醒、空標題、TODO、TBD 或 placeholder。
- 不臆造病例細節；一般外部補充只出現在編輯補充欄位。

### 影格與路徑

- 每章原則上有 1–4 張有效主要影格，目標為 4 張；完全無圖即失敗。
- 每張影格檔案存在、格式可讀、相對路徑可由 viewer 解析。
- 影格時間合法且位於章節範圍或統一容許的邊界誤差內。
- 不以重複、純黑、嚴重模糊、無關或 placeholder 影像補足數量。
- 4 張影格在 viewer 中等尺寸且完整顯示；不足 4 張時不得出現空白格。

### 衍生檔一致性

- JSON、viewer、PBF 與 `.v4.md` 的章節數、順序、起訖時間與標題一致。
- `.v4.md` 的整理稿、核心重點與編輯補充與 JSON 同步。
- 課程首頁的 11 講清單、連結與完成狀態和正式產物一致。
- 稽核報告能追溯每個產物的輸入、結果與失敗原因。

### Viewer 功能

- 影片可載入與播放。
- 章節導覽、深連結與跳播時間正確。
- 主要縮圖可見、可放大並可跳至對應時間。
- 搜尋可命中各內容欄位與逐字稿，結果可正確導航。
- 逐字稿可展開、閱讀並與播放時間同步。
- 桌面與窄螢幕版面均無關鍵內容遮擋、溢位或不可操作控制項。

任何必須門檻失敗時，該講不得替換正式檔。只要任一講未通過，全課首頁不得切換至重建版本。

## 測試策略

### 單元測試

至少涵蓋：

- 標題規則與禁止模式。
- `summary_zh` 長度與段落檢查。
- `takeaways_zh` 正好 4 項。
- `editorial_notes_zh` 欄位與來源分離規則。
- 繁簡體、TODO/TBD、模板提醒、空字串與 placeholder 偵測。
- frame 數量、時間範圍、相對路徑與檔案存在性。
- 章節時間不變性。
- JSON、viewer、PBF 與 `.v4.md` 的一致性比較。
- 備份命名、暫存驗證、單講失敗隔離及原子替換行為。

### Fixture 整合測試

建立不含敏感資料的小型 fixture，包含 MP4/SRT/JSON/frames/OCR 的代表性組合，驗證從 extract 到 audit 的完整流程。fixture 應涵蓋：

- 正常四圖章節。
- 僅有 1–3 張有效影格的章節。
- 完全無有效影格而必須失敗的章節。
- OCR 空值、重複影格、非法路徑及時間越界。
- 一講失敗但其他講仍可完成的批次情境。

### 三講抽樣驗證

Brain tumor、Vascular、Spine 三講各自檢查：

- 章節內容是否符合該領域的判讀邏輯與常用術語。
- 重寫是否忠於原始資料且未臆造病例細節。
- 影格是否具代表性，OCR 是否有助於辨識主題。
- viewer、PBF、`.v4.md` 與 JSON 是否一致。
- 搜尋、縮圖、逐字稿、深連結與跳播是否可用。

### 11 講全課驗證

- 11 講均通過 schema、內容、影格、路徑與衍生檔一致性稽核。
- 每章至少有 1 張有效主要影格，且零圖章節數為 0。
- 所有影片、縮圖、搜尋索引、深連結與逐字稿資源可載入。
- 全課標題與術語風格一致。
- 只有全課通過後才產生並更新正式課程首頁。

### 瀏覽器 E2E

以實際 viewer 驗證：

- 章節導覽與目前章節狀態。
- 1–4 張縮圖的顯示、放大與跳播。
- 標題、摘要、核心重點與編輯補充的版面層級。
- 搜尋各內容欄位與逐字稿後的導航。
- 逐字稿展開、時間同步與點擊跳播。
- 章節深連結直接載入。
- 桌面寬度與窄螢幕寬度下的可讀性及操作性。

### 獨立驗證

實作完成後由 fresh-context 驗證者依本規格 read-back 並執行代表性測試，不以實作者自行檢查取代。驗證結果應列出通過項、失敗項、測試證據與尚未處理的風險。

## Rollout 與回復

1. 完成 canonical 生成器與單元、fixture 測試。
2. 完成 Brain tumor、Vascular、Spine 三講抽樣，經人工與 E2E 驗證通過。
3. 對 11 講執行全課重建，失敗講次保留原檔並可個別重跑。
4. 全課稽核通過後，以原子替換逐講切換正式產物。
5. 再次執行全課瀏覽器 smoke/E2E 測試。
6. 最後更新課程首頁，使其一次指向完整的新版本。

若正式切換後發現阻斷性問題，依日期備份回復受影響講次的 JSON、viewer、PBF、`.v4.md` 與首頁。回復後重新執行一致性與 viewer smoke test，確認課程回到可用狀態。備份在確認新版本穩定前不得刪除。

## 驗收條件

本設計後續實作完成時，須同時符合：

- canonical `skills/lecture-to-notes/` 可重建 NR 全課，沒有 NR 專用長期分岔或一次性 NAS hotfix。
- 11 講 JSON 均符合資料模型與內容規則，且章節起訖時間未改變。
- 每章有聚焦標題、約 250–600 字整理稿、正好 4 項核心重點與分離的編輯補充。
- 每章至少 1 張、最多 4 張有效主要影格，目標為 4 張，完全無圖的章節不得通過。
- viewer 保留播放器、章節、搜尋、深連結、同步逐字稿及跳播，並正確呈現主要影格與編輯補充。
- JSON、viewer、PBF、`.v4.md`、課程首頁與稽核報告的章節資料一致。
- 安全寫入、日期備份、暫存驗證、原子替換、失敗隔離、進度回饋及回復流程均有測試證據。
- 單元測試、fixture 整合測試、三講抽樣、11 講全課稽核、瀏覽器 E2E 與 fresh-context 驗證全部通過。
- `python sync_skills.py` 與 `python sync_skills.py --check` 成功完成。
- Git 只提交實作所需的程式與測試；NAS 產物、敏感資料及無關檔案不得進入版本控制。
