# 2026 下半年舊戶信用卡回饋資料庫與查詢工具設計

**日期：** 2026-08-17  
**狀態：** 待使用者書面確認  
**目標期間：** 2026-08-01 至 2026-12-31  
**適用資格：** 既有持卡人／既有存款客戶；排除所有新戶、新卡首刷與新申辦限定優惠

## 1. 目標

先建立一套可追溯、可更新的 Markdown 回饋資料庫，再以該資料庫製作一個類似 Claude artifact 的靜態查詢工具。使用者應能快速回答：在指定消費場景下，現有卡片中哪張回饋較高、需要完成哪些條件，以及最多可拿到多少回饋。

研究階段只寫入官方來源明確支持的內容。若銀行尚未公告涵蓋至 2026-12-31 的方案，應保留已查證的較短有效區間並標示「後續期間待公告」，不得沿用舊方案或自行推估。

## 3. 非目標

- 不納入新戶、新卡、首次綁定、首刷禮或新開戶專案。
- 不把抽獎、贈品或不保證取得的回饋換算成固定回饋率。
- 不保證涵蓋市場上所有信用卡，只比較使用者列出的產品。
- 不處理哩程價值、點數主觀估值或年費成本最佳化。
- 不登入網銀、銀行 App 或個人帳戶，也不讀取個人消費資料。
- 研究階段不修改現有 Claude artifact；完成資料驗收後才建立 repo 內的靜態工具。

## 5. 單卡資料格式

每份卡片 Markdown 使用相同欄位：

```yaml
---
product: "正式產品名稱"
issuer: "發卡或發行銀行"
product_type: credit | debit | atm
customer_scope: existing
target_from: 2026-08-01
target_to: 2026-12-31
verified_at: 2026-08-17
coverage_status: complete | partial | unavailable
---
```

正文固定包含：

1. **結論摘要**：國內一般、國外一般與最值得注意的特殊回饋。
2. **一般回饋**：回饋率、回饋形式、門檻、上限、有效區間。
3. **特殊回饋**：通路或場景、總回饋率、基本／加碼拆分、條件、上限與可刷金額。
4. **行動支付相容性**：LINE Pay、iPASS MONEY、全支付是否可綁、是否被排除、能否取得原卡回饋。
5. **排除交易**：稅費、保費、超商代收、儲值、分期、電子支付儲值等官方列明項目。
6. **來源證據**：官方活動頁、權益頁、PDF 或公告的直接連結、頁面標題、有效期間與查證日期。
7. **不確定事項**：尚未公告、來源衝突、名額或登錄狀態無法確認的內容。

## 6. 回饋正規化規則

### 有效期間

- 研究視窗固定為 2026-08-01 至 2026-12-31。
- 活動只涵蓋部分視窗時，保留實際 `valid_from` 與 `valid_to`，不得標示為全年有效。
- 若活動在查證日已額滿、提前終止或內容變更，以最新官方公告為準並保留變更註記。

### 回饋率

- 同時記錄「總回饋率」與「基本回饋＋活動加碼」的組成。
- 「最高 X%」只有在條件可完整描述時才列入比較；否則標示為條件式宣傳值。
- 點數與現金分開記錄。只有官方明示 1 點等值新台幣 1 元時，才可在顯示層並列為等值百分比。

### 上限與可刷金額

- 保留官方上限單位：每月、每期、每季、每活動或每戶。
- 可計算時顯示加碼可刷金額：`加碼回饋上限 ÷ 加碼回饋率`。
- 計算結果應標示為推導值，並保留原始上限和加碼率，避免把總回饋率誤用為分母。
- 名額限制、登錄時間與額滿狀態獨立列出，不與金額上限混為一談。

### 舊戶資格

- 只納入既有持卡人或既有帳戶可參加的方案。
- 同一頁若同時包含新戶與舊戶優惠，只摘錄舊戶適用段落並明確排除新戶條款。
- 無法確認舊戶適用性時，不列為可用回饋，改列於不確定事項。

## 7. 來源與證據品質

來源優先序：

1. 銀行或支付服務官方活動辦法／權益 PDF。
2. 銀行或支付服務官方產品頁與公告。
3. 官方新聞稿，僅用於補足正式活動頁已載明的內容。

第三方理財網站、社群文章、論壇或搜尋摘要可以用來發現線索，但不得作為最終回饋數字的唯一證據。每個列入比較表的方案至少要有一個直接官方來源。

官方頁面若為動態頁、圖片或 PDF，需記錄可重現的頁面標題、活動期間與定位資訊。來源失效時保留「來源目前無法重開」狀態，不以記憶補寫。

## 8. 跨卡比較與行動支付

`comparison.md` 至少包含：

| 欄位 | 說明 |
|---|---|
| 產品 | 正式卡名或金融卡名 |
| 國內一般 | 回饋率、形式與上限 |
| 國外一般 | 回饋率、海外手續費提醒與上限 |
| 最佳特殊回饋 | 場景、總率與必要條件 |
| 加碼上限 | 原始上限及推導可刷額 |
| 常用支付 | LINE Pay／iPASS MONEY／全支付適用性 |
| 覆蓋狀態 | 完整、部分期間、待公告或無消費功能 |

行動支付文件以支付服務為主軸，列出：可連結的使用者卡片或帳戶、支付服務本身的舊戶活動、原卡回饋是否可能疊加，以及官方明確排除的交易型態。不得因「可以綁卡」就推論「一定有卡片回饋」。

## 9. 後續靜態查詢工具

資料驗收後建立 `tool/card-rewards.html`，採 repo 既有的自包含靜態工具模式，不依賴 React、CDN、外部字型或執行時 API。研究 Markdown 是內容與證據的來源，工具內嵌一份由受控轉換產生的結構化資料。

預計功能：

- 卡片總表與單卡明細。
- 店家、場景、卡名與支付方式搜尋。
- 國內、國外、網購、行動支付等分類篩選。
- 顯示回饋率、任務、登錄、上限、可刷金額和有效期間。
- 來源連結與最後查證日期。
- 對部分期間、待公告、需登錄、限量及推導值使用明顯標記。
- 手機與桌面響應式版面。

完成後將 `index.html` 與 `README.md` 的 Claude artifact 外部連結改成相對路徑 `tool/card-rewards.html`。現有 artifact 保留為歷史參考，不作為新工具的資料來源。

## 10. 錯誤與不完整資料處理

- 官方來源找不到：標示 `unavailable`，說明已查詢範圍，不填入猜測值。
- 只公告至 9/30：以 `partial` 記錄 8/1–9/30，10/1–12/31 標示待公告。
- 同一官方來源前後衝突：優先使用日期較新且明示修訂的公告，並記錄衝突。
- 活動需登錄但無法確認額滿：標示「需即時確認名額」，不得顯示為保證取得。
- 金融卡僅有提款功能：一般刷卡回饋填「不適用」，另列帳戶連結支付活動。
- 海外交易：分開呈現回饋與國外交易服務費，不用名目回饋率直接宣稱淨回饋。

## 11. 驗證策略

### 研究資料

- 15 個產品及 3 個行動支付文件全部存在。
- 每份文件包含完整 frontmatter、固定章節、至少一個官方來源或明確的 `unavailable` 說明。
- 比較表中的數字可回溯至單卡文件，單卡文件可回溯至官方來源。
- 自動檢查日期格式、URL、舊戶範圍、覆蓋狀態及必要欄位。
- 人工複核最高回饋、加碼上限與可刷金額計算，避免把基本回饋重複相加。

### 靜態工具

- 測試所有研究產品均出現在資料與介面中。
- 測試搜尋別名、分類篩選、展開明細與來源連結。
- 測試部分期間、待公告、需登錄及限量標記。
- 測試桌面與手機主要操作流程。
- 驗證完全離線載入時仍可瀏覽既有資料；只有點擊官方來源時才連網。
- 執行既有首頁導覽測試、專案相關單元測試與 `git diff --check`。

## 12. 執行與版本控制邊界

- 研究與實作在獨立 Git worktree／`codex/` 分支完成，避免碰觸目前 `main` 的既有未提交變更。
- 只 stage 本變更明確列出的規格、研究文件、工具、測試、README 與首頁路徑。
- 研究資料完成並通過驗證後，先交付查證摘要與未解項目；使用者核定後才開始介面製作。
- 不發布、不推送、不建立 PR，除非使用者另外授權。

## 13. 驗收條件

研究階段完成需同時符合：

1. 15 個產品與 3 個行動支付均有 Markdown 文件。
2. 每項可用回饋都有官方來源、有效期間、舊戶資格、條件與上限。
3. 2026-08-01 至 2026-12-31 未被官方資料覆蓋的區間均明確標示待公告。
4. `comparison.md` 可直接比較國內、國外、特殊回饋與常用支付。
5. 沒有把新戶優惠、抽獎或不確定回饋當成固定收益。
6. 驗證命令通過，且未修改或 stage 任何既有無關變更。

工具階段完成需另符合：

1. `tool/card-rewards.html` 可自包含離線開啟。
2. 介面資料與核定的 Markdown 一致，所有數字可追溯至官方來源。
3. 搜尋、分類、比較、條件展開與來源檢視均通過測試。
4. `README.md` 與 `index.html` 改連至 repo 內工具。
5. 手機與桌面瀏覽器完成實際操作驗證。
