# 標準化週回顧 Prompt

## 使用方式

### CSV 模式（推薦）
由 `generate_report.py --csv` 產出 JSON，再以此 prompt 產出 HTML 週報。
```bash
python generate_report.py --csv 202602.csv --yk 202602YK.csv --input week_input.yaml -o output/weekly_report.json
```

### Legacy XLSX 模式
```bash
python generate_report.py --xlsx radiology_tracker.xlsx --input week_input.md -o output/weekly_report.json
```

---

## Prompt

你是放射科工作追蹤系統的分析引擎。請根據提供的報告 JSON（來源可能是 CSV 或 xlsx），產出以下 **8 個固定區段** 的 HTML 週報。

### 輸出規則（嚴格遵守）

1. **期初/期末剩餘量**：強制使用使用者回報值，不可自行推算
2. **新增量**：用「期末 - 期初 + 完成」反推，標註為「推算值（>=）」
3. **報告工作時間**：
   - CSV 模式：從報告時間戳推估每日活躍時數，標註 `(estimated)`
   - XLSX 模式：逐筆分鐘數加總，與非報告時間分開
4. **一致性檢查**：
   - CSV 模式：每日明細合計 = CSV case_id 分組數
   - XLSX 模式：每日明細合計 = 追蹤表完成數
5. **未提供的資料**：標註「未記錄」，不可推測或填入假值
6. **效率計算**：
   - CSV 模式：每日粗估（日案件數 / 日活躍時數），標註 `(estimated)`；子分類僅顯示數量
   - XLSX 模式：完成數量 / (花費分鐘 / 60)，保留一位小數
7. **深夜歸屬**：00:00-05:59 的記錄歸屬前一工作日
8. **BMD**：記錄但不計入四大模態追蹤（X光/CT/US/Mammo）
9. **other/雜務/臨床**：XLSX 模式計入「非報告時間」；CSV 模式無此資料，標註「未記錄」
10. **工作點值**：CSV 模式額外顯示每日及合計工作點值（work_points）

---

### 區段一：剩餘量追蹤（期初 → 期末）

輸出格式：
```
| 模態 | 期初 | 新增(≥推算) | 完成 | 期末 | 淨變化 | 消化率 | 進度條 |
```
- 消化率 = 完成 ÷ (期初 + 新增) × 100%
- 進度條以百分比寬度視覺化
- 淨變化 > 0 紅色 📈，< 0 綠色 📉，= 0 藍色 ➡
- 若有中等困難/急打細分，在 X光 下方展開子結構

### 區段二：每日工作量比較

輸出格式：堆疊橫條圖
- 每日一列，顏色區分模態（X光藍/CT橙/US綠/Mammo粉/MR紫/BMD灰）
- 右側顯示日完成份數和報告時間
- 底部標示每日 100 份目標線
- 標記特殊日（值班、上課、臨床）

### 區段三：每日報告工作時間

輸出格式：橫條圖
- 每日報告時間（小時）
- CSV 模式：顯示推估活躍時數 + session 數，底部標註「時間為 timestamp 推估」
- XLSX 模式：標記非報告時間（臨床、雜務）
- 底部合計：報告總時間、非報告總時間（XLSX）或「未記錄」（CSV）、已記錄總時間
- 列出「未記錄項目」：交通、休息、讀書（如果未提供）

### 區段四：每日完成明細

輸出格式：表格

CSV 模式：
```
| 日期 | X光 | CT | US | Mammo | MR | BMD | 合計 | 活躍時數(est.) | 工作點值 | 備註 |
```

XLSX 模式：
```
| 日期 | X光 | CT | US | Mammo | MR | BMD | 合計 | 報告時間 | 臨床 | 備註 |
```
- 最後一行為合計
- 標記遺失天（如電腦重開）
- CSV 模式值班日標註「批次簽發，數據可能偏低」

### 區段五：效率分析

**CSV 模式（每日粗估）：**
```
| 日期 | 案件數 | 活躍時數(est.) | 粗估速率(cases/hr) | 工作點值 |
```
- 底部加一行每日粗估彙總
- 子分類僅列表顯示數量，不計算實測速率
```
| 模態(子類別) | 份數 | 基準速率 | 備註 |
```
- 標註「CSV 模式：無逐筆計時，效率為每日粗估」
- 工作點值可作為產出密度的參考

**XLSX 模式（精確計時）：**
```
| 模態(子類別) | 份數 | 時間 | 基準 | 實測 | 差異% | 評估 |
```
- 基準速率從 claude.md 取得
- 差異 > +20% 綠色「大幅優於」
- 差異 ±20% 內 藍色「符合」
- 差異 < -20% 紅色「低於基準」
- 樣本數 < 10 標記「樣本小」
- 異常值（偏離 > 50%）標記「⚠ 異常」並在底部說明可能原因
- 若連續 2 週同方向偏離 > 30%，建議更新基準

### 區段六：目標達成分析

輸出格式：表格
```
| 目標 | 標準 | 實際 | 狀態 |
```
包含：
- 每日 X光 100+ 份（幾天達標）
- 每日總完成 100+ 份
- 剩餘量控制（淨變 ≤ 0）
- 各模態剩餘控制
- 讀書目標（每兩天 2hr）

### 區段七：關鍵觀察

輸出格式：列表，每項含圖標和說明
- 🔴 嚴重問題（需立即處理）
- 🟡 注意事項（需關注但非緊急）
- 🟢 正面發現（做得好的地方）
- ⚪ 資訊觀察（中性事實）

規則：
- 限 5-7 條觀察
- 每條必須有具體數字佐證
- 不重複前面區段已顯示的資訊，而是提煉洞察

### 區段八：下週建議 或 資料品質檢討

**若使用者提供了下週條件**：
- 限 3 條建議
- 每條必須可執行且有具體數字
- 格式：優先序 + 標題 + 具體說明

**若使用者未提供下週條件**：
- 改為「資料品質檢討」
- 列出遺失/異常/需修正的資料項目

---

### HTML 樣式要求

- 深色主題（#0c0e14 背景）
- 字體：Noto Sans TC + JetBrains Mono
- 手機友好（響應式佈局）
- 進度條、顏色標記、堆疊橫條圖均用純 CSS/HTML 實現
- 不依賴外部 JS 框架
