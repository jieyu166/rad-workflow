# 標準化週回顧 Prompt

## 使用方式

### CSV 模式（推薦）
由 `generate_report.py --csv` 產出 JSON，再以此 prompt 產出 HTML 週報。
```bash
python generate_report.py --csv 202602.csv --yk 202602YK.csv --input week_input.yaml -o output/weekly_report.json
```

### Legacy XLSX 模式
```bash
python generate_report.py --xlsx radiology_tracker.xlsx --input week_input.md -o output/weekly_report.json
```

## Prompt

你是放射科工作追蹤系統的分析引擎。請根據提供的報告 JSON（來源可能是 CSV 或 xlsx），產出以下 **8 個固定區段** 的 HTML 週報。

### 輸出規則（嚴格遵守）

1. **期初/期末剩餘量**：強制使用使用者回報值，不可自行推算
2. **新增量**：用「期末 - 期初 + 完成」反推，標註為「推算值（>=）」
3. **報告工作時間**：
   - CSV 模式：從報告時間戳推估每日活躍時數，標註 `(estimated)`
   - XLSX 模式：逐筆分鐘數加總，與非報告時間分開
4. **一致性檢查**：
   - CSV 模式：每日明細合計 = CSV case_id 分組數
   - XLSX 模式：每日明細合計 = 追蹤表完成數
5. **未提供的資料**：標註「未記錄」，不可推測或填入假值
6. **效率計算**：
   - CSV 模式：每日粗估（日案件數 / 日活躍時數），標註 `(estimated)`；子分類僅顯示數量
   - XLSX 模式：完成數量 / (花費分鐘 / 60)，保留一位小數
7. **深夜歸屬**：00:00-05:59 的記錄歸屬前一工作日
8. **BMD**：記錄但不計入四大模態追蹤（X光/CT/US/Mammo）
9. **other/雜務/臨床**：XLSX 模式計入「非報告時間」；CSV 模式無此資料，標註「未記錄」
10. **工作點值**：CSV 模式額外顯示每日及合計工作點值（work_points）

### 區段一：剩餘量追蹤（期初 → 期末）

輸出格式：
```
| 模態 | 期初 | 新增(≥推算) | 完成 | 期末 | 淨變化 | 消化率 | 進度條 |
```
- 消化率 = 完成 ÷ (期初 + 新增) × 100%
- 進度條以百分比寬度視覺化
- 淨變化 > 0 紅色 📈，< 0 綠色 📉，= 0 藍色 ➡
- 若有中等困難/急打細分，在 X光 下方展開子結構

### 區段二：每日工作量比較

輸出格式：堆疊橫條圖
- 每日一列，顏色區分模態（X光藍/CT橙/US綠/Mammo粉/MR紫/BMD灰）
- 右側顯示日完成份數和報告時間
- 底部標示每日 100 份目標線
- 標記特殊日（值班、上課、臨床）

### 區段三：每日報告工作時間

輸出格式：橫條圖
- 每日報告時間（小時）
- CSV 模式：顯示推估活躍時數 + session 數，底部標註「時間為 timestamp 推估」
- XLSX 模式：標記非報告時間（臨床、雜務）
- 底部合計：報告總時間、非報告總時間（XLSX）或「未記錄」（CSV）、已記錄總時間
- 列出「未記錄項目」：交通、休息、讀書（如果未提供）

### 區段四：每日完成明細

輸出格式：表格

CSV 模式：
```
| 日期 | X光 | CT | US | Mammo | MR | BMD | 合計 | 活躍時數(est.) | 工作點值 | 備註 |
```

XLSX 模式：
```
| 日期 | X光 | CT | US | Mammo | MR | BMD | 合計 | 報告時間 | 臨床 | 備註 |
```
- 最後一行為合計
- 標記遺失天（如電腦重開）
- CSV 模式值班日標註「批次簽發，數據可能偏低」

### 區段五：效率分析

**CSV 模式（每日粗估）：**
```
| 日期 | 案件數 | 活躍時數(est.) | 粗估速率(cases/hr) | 工作點值 |
```
- 底部加一行每日粗估彙總
- 子分類僅列表顯示數量，不計算實測速率
```
| 模態(子類別) | 份數 | 基準速率 | 備註 |
```
- 標註「CSV 模式：無逐筆計時，效率為每日粗估」
- 工作點值可作為產出密度的參考

#### 區段五-b：平日時段 cases/hr 折線圖（每週必做，2026-06-23 起）

資料來自 JSON `hourly_weekday` 欄位（由 `generate_report.py` 自動產出，鍵為 "0"~"23"，值含 `n`/`cph`/`irate`/`med`/`top`）。

- 畫一張 **08–23 時的 cases/hr 折線圖**（純 SVG，深色主題；可直接呼叫 `tod_efficiency.linechart_svg()` 的同款樣式）
- 只連有 `n>0` 的點，避免假性下凹；`n<30` 的點淡化（opacity 0.4）
- X 軸 = 整點 8..23、Y 軸 = cases/hr；標出當週最高/最低時段
- 底部一句話：本週你最有效率的時段（對照全期基準：午後 13-17 最高、晚間 19-23 最低）
- 註：cases/hr 由相鄰簽發間隔推估（>20min 截斷），report_time 精度到分；批次簽發時段會偏高，需對照件數與模態判讀
- 若 `hourly_weekday_meta.weekday_cases < 30`，標「本週平日樣本不足，折線僅供參考」
- 全期完整 0–23 熱力圖（含平日/假日對照）見 `output/tod_efficiency.html`，每月由 `build_trends.py` 自動更新至 `output/trends.html` 區段九

**XLSX 模式（精確計時）：**
```
| 模態(子類別) | 份數 | 時間 | 基準 | 實測 | 差異% | 評估 |
```
- 基準速率從 claude.md 取得
- 差異 > +20% 綠色「大幅優於」
- 差異 ±20% 內 藍色「符合」
- 差異 < -20% 紅色「低於基準」
- 樣本數 < 10 標記「樣本小」
- 異常值（偏離 > 50%）標記「⚠ 異常」並在底部說明可能原因
- 若連續 2 週同方向偏離 > 30%，建議更新基準

### 區段六：目標達成分析

輸出格式：表格
```
| 目標 | 標準 | 實際 | 狀態 |
```
包含：
- 每日 X光 100+ 份（幾天達標）
- 每日總完成 100+ 份
- 剩餘量控制（淨變 ≤ 0）
- 各模態剩餘控制
- 讀書目標（每兩天 2hr）

### 區段七：關鍵觀察

輸出格式：列表，每項含圖標和說明
- 🔴 嚴重問題（需立即處理）
- 🟡 注意事項（需關注但非緊急）
- 🟢 正面發現（做得好的地方）
- ⚪ 資訊觀察（中性事實）

規則：
- 限 5-7 條觀察
- 每條必須有具體數字佐證
- 不重複前面區段已顯示的資訊，而是提煉洞察

### 區段八：下週建議 或 資料品質檢討

**若使用者提供了下週條件**：
- 限 3 條建議
- 每條必須可執行且有具體數字
- 格式：優先序 + 標題 + 具體說明

**若使用者未提供下週條件**：
- 改為「資料品質檢討」
- 列出遺失/異常/需修正的資料項目

### 區段十：切片/FNA 追蹤 & 介入處置回顧

資料來自 JSON `biopsy_followup` 欄位（由 `biopsy_tracker.py` 自動產出）。

#### ⚠ 追蹤日的正確解讀（2026-08-10 使用者釐清，勿再誤報）

`followup_date = 執行日 +7d` 是**登錄用的行政目標，不是臨床 SLA**：

- **病理科報告本來就需要較久**，超過 +7d 屬正常週轉，不代表延誤
- **病人會回診，由臨床醫師處理後續**——放射科追蹤表不驅動臨床行動
- 本表用途是 **QC／稽核**（Thyroid ND 率、Breast PPV、B3 追蹤），不是病人安全警示
- **Breast CNB 惡性率 ~40% 符合 BI-RADS 規範**（BI-RADS 4/5 病灶的預期 PPV）；**Thyroid FNA 以良性為主亦屬正常分布**——兩者都不是異常訊號

⇒ 逾期案件請以**中性語氣**列出（「尚未登錄結果」），**不要標紅、不要寫「立即確認／風險」**，也不要因為某件逾期案結果是惡性就回頭推論追蹤流程有問題。

#### 10a. 本週病理追蹤提醒（尚未登錄結果者）

列出「上週執行、本週應已可查病理報告」的案件：

```
| 程序類型 | 執行日 | 追蹤日(+7d) | 病歷號 | 狀態 |
```

- `biopsy_due_now` 清單對應本欄位
- 「狀態」欄留空白讓使用者手動填入（adequate / inadequate / pending）
- 若清單為空，顯示「本週無待追蹤案件」

追蹤程序類型說明：
| 程序 | 臨床意義 |
|------|----------|
| Thyroid FNA | 甲狀腺細針抽吸，確認是否足夠細胞量 |
| US-Neck FNA | 頸部淋巴結/其他 FNA |
| Breast CNB | 乳房核心切片（19007-1+29035-1），確認病理結果 |
| Mammo Stereotactic Bx | 立體定位切片，高優先確認 |
| CT-Biopsy | CT 導引切片，確認是否有效取樣 |

#### 10b. 本週執行切片/FNA（下週需追蹤）

列出本週執行的切片案件，提醒下週查病理：

```
| 程序類型 | 執行日 | 追蹤截止日(+7d) | 病歷號 |
```

- `biopsy_this_week` 清單對應本欄位
- 若清單為空，顯示「本週無新執行切片」

#### 10c. 本週介入處置

列出本週執行的介入項目（不需病理追蹤，供回顧參考）：

```
| 日期 | 程序 | 代碼 | 病歷號 |
```

- `interventional` 清單對應本欄位
- 各類別點值說明（可選）：PCN 44.9pt、PTGBD 34.6pt、引流 71.3pt、關節攝影 18.3pt

#### 10d. 樣式規則

- 追蹤提醒用醒目色框（橘/紅）凸顯「應立即確認」
- 下週待追蹤用藍色框
- 介入處置用灰色/暗色框
- 每列包含可視顏色標籤區分程序類型：
  - Thyroid/Neck FNA → cyan
  - Breast CNB / Mammo Bx → pink
  - CT-Biopsy → orange

### 區段十二：報告單位時間產值（2026-05-27 起；改為真實計時）

回答「哪種報告單位時間最賺錢（pt/hr）」。**全模態**，資料來自 `xr_value.py` 的 JSON（如 `output/xr_value_{month}.json`）。

#### 計時方法（真實 CSV 簽發間隔，非估算）
- 依 case_id 取最早簽發時間，全 case 排序，每件耗時 = 與前一件的簽發間隔
- 間隔 = 0（同分鐘批次）→ 剔除；間隔 > 30min（休息）→ 剔除
- pt/hr = 平均點值 × 60/中位間隔(min)

#### 12a. 產值排名表（依 pt/hr 排序，列 20-30 類）

```
| 類別 | n件 | n計時 | 中位 min | 平均點值 | pt/hr |
```

- **全模態 + 子分類**：CT(LDCT/Brain/Neck/Chest)、US(一般/困難)、XR 部位
- **Spine 依 protocol 拆**：AP/Lat、Flex/Ext、4view（Flex/Ext 較慢、pt/hr 較低）
- **平均點值**＝硬數據；**pt/hr**＝真實間隔中位數推算
- 計時樣本 n < 15 標「⚠少」（不納入可信排名）

#### 12b. 重點呈現（典型結論，2026-05 大樣本）
- 🥇 **Mammo (422) / XR Knee (409)** 並列最賺
- 高產值：Shoulder、L/C-spine AP/Lat、BMD、US 一般
- 低產值高量：**Chest (97, 但佔量 30%)**、CT/LDCT（中位 15-18min 真的慢）

#### 12c. 樣式
- 冠軍綠標；Chest 標「量大值低」；低樣本標 ⚠少
- 註明：pt/hr 真實間隔中位（report_time 僅到分→次分鐘 floor 1min）

#### 12d. 操作流程

```bash
# 建議餵多週/整月 CSV 累積足夠計時樣本
python xr_value.py --csv csv_input/115*_CL.csv --min-n 15 --json output/xr_value_{month}.json
```

> 用途：門診 XR 無法全做時，優先讀高 pt/hr 部位（Knee/Shoulder/多 view 肌骨）。
> 注意：臨床重要性（如 Chest 肺結節）不可純以點值取捨。

### 區段十三：出勤補登草稿（每週結算必做，2026-07-23 起）

**用途**：從報告時間戳推算每日簽到/簽退草稿，供使用者**手動**輸入奇美「主治醫師刷卡補登作業」網頁。**純資料輸出，不串接網頁、不自動提交。**

資料來源：`attendance_draft.py` 產生的 JSON（如 `output/attendance_W{NN}.json`）。

```bash
python attendance_draft.py --csv csv_input/{week_csv}.csv \
  --json output/attendance_W{NN}.json --out-csv output/attendance_W{NN}.csv
```

#### 13a. 工作段模型（務必照此，勿改回日曆日）

- **深夜 00:00–05:00 的簽發＝前一工作日的延續** → 併入前一日，該日**簽退跨日**
- **簽到不早於 06:00**（早上最早開始）；收工通常不超過 04:00
- 例：07/19(日) 21:59→07/20 02:14 ⇒ 簽到 21:14、簽退 **07/20 02:34**

#### 13b. 表格欄位（放在報告最下方，方便逐日對照抄寫）

```
| 工作日 | 週 | 件數 | 最早報告 | 最晚報告 | 簽到 | 簽退 | 時數 | 備註 |
```

- 簽到 = 最早報告 −45min（夾在 06:00）；簽退 = 最晚報告 +20min（緩衝可調）
- **跨日簽退顯示日期**（如 `07/20 02:34`）
- 時間欄位用 `JetBrains Mono` 等寬字型並加大，方便照著打字
- 有備註者整列標黃底提示需人工確認

#### 13c. 必附提醒

- 「此為草稿，請人工檢視後再補登」
- 手動流程：`#DDL_date` 選日期 → `#txt_HHMM` 填時間 → 按 `#btnSubmit`；逐筆送出、系統依打卡狀態自動判定簽到/簽退，前端不區分。**跨日簽退用它自己的日期送出**
- ⚠ **只反映「簽報告」時間**：當天若上午做臨床/開會/處置而未簽報告，簽到會被低估 → 標「簽到偏晚需確認」，請人工補正

### HTML 樣式要求

- 深色主題（#0c0e14 背景）
- 字體：Noto Sans TC + JetBrains Mono
- 手機友好（響應式佈局）
- 進度條、顏色標記、堆疊橫條圖均用純 CSS/HTML 實現
- 不依賴外部 JS 框架
